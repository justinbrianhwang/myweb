Compilers

AI/ML · Hardware-aware · Quantum · Classical Compiler & Programming-Language Theory

Overview

Compiler research is the connective tissue between high-level program intent and the physical hardware that executes it. Whether the target is a deep learning accelerator, an FPGA inference engine, a noisy quantum processor, or a conventional CPU, the same questions resurface: what does the program mean, what does the hardware allow, and how do we close the gap with provably correct transformations?

My work spans four complementary directions of compiler technology, intentionally chosen so that ideas in one direction inform the others — graph-level rewrites in ML compilers borrow from classical dataflow analysis, qubit routing borrows from register allocation, and FPGA scheduling borrows from polyhedral loop optimization.

1. AI / ML Compilers

Modern deep learning models are compiled, not just executed. Frameworks such as TVM, XLA, and MLIR lower high-level model graphs through a series of intermediate representations, applying graph-level rewrites and operator-level optimizations before generating code for a specific accelerator.

  • Graph-level optimization passes — operator fusion, constant folding, layout transformation, common subexpression elimination on computation graphs.
  • Operator scheduling and tiling — choosing loop orders, tile sizes, and parallelization strategies that match the target's memory hierarchy.
  • Autotuning — search over the space of valid schedules (XGBoost-based cost models, evolutionary search) to find configurations that maximize throughput.
  • Quantization-aware compilation — folding INT8/FP16 conversion into operator fusion to deliver low-precision inference without accuracy loss.

2. Hardware-aware Compilation

Compiling neural networks for edge accelerators is fundamentally different from compiling C for an x86 server. The compiler must reason explicitly about memory hierarchies, dataflow patterns, and backend-specific resource constraints to deliver low-latency inference at minimum power.

  • FPGA backends — high-level synthesis (HLS) from operator graphs to RTL, with systolic-array and dataflow templates for matrix multiplication, convolution, and attention layers.
  • GPU backends — CUDA / HIP kernel generation, warp-level scheduling, shared-memory tiling, and tensor-core specialization.
  • NPU backends — mapping graphs onto vendor-specific accelerators (NVDLA-style, mobile NPUs) with explicit DMA and double-buffering schedules.
  • Polyhedral optimization — affine transformations of perfectly nested loops to expose parallelism, tile for cache, and eliminate redundant memory traffic.

3. Quantum Compilers

Quantum programs written against an idealized gate set cannot run directly on real NISQ (noisy intermediate-scale quantum) hardware. A quantum compiler must rewrite logical circuits so that they respect the connectivity, native gate set, and noise profile of the target device — all while preserving the program's semantics.

  • Circuit optimization — gate cancellation, commutation rewrites, and template matching to reduce depth and gate count.
  • Gate synthesis and decomposition — lowering arbitrary unitaries into hardware-native gates (CX, RZ, SX on IBM hardware; CZ, U3 on others).
  • Qubit routing and SWAP insertion — mapping logical qubits to physical ones and inserting minimal SWAP gates to satisfy the coupling graph.
  • Noise-aware transpilation — selecting routes and gate sequences that minimize accumulated error using device calibration data.

4. Classical Compiler & Programming-Language Theory

Underpinning all of the above is the long tradition of compiler infrastructure and programming-language semantics, built on production tooling such as LLVM and on decades of work on formal methods. The directions of research that interest me most are those that make optimizations provably correct.

  • LLVM-based static analysis — building dataflow and alias analyses on top of LLVM IR, then exposing them as optimization passes.
  • Program transformations — loop optimization, SSA-based rewrites, escape analysis, devirtualization.
  • Formal semantics for optimizations — defining operational or denotational semantics for IR fragments so that transformations can be machine-checked.
  • Type-driven program reasoning — using dependent and refinement types to express invariants that the compiler can verify and exploit.

Why this thread matters

Every other research area I work on — AI semiconductors, quantum computing, autonomous driving, edge medical AI — ultimately runs on a compiler. The performance, correctness, and even the energy budget of those systems are largely determined by decisions that a compiler makes silently between the user's model and the executing hardware. Treating compilers as a first-class research thread lets the rest of the stack be designed coherently rather than in isolation.
